# Переезд сайта с GitHub Pages на Timeweb Cloud

Сайт остаётся в этом репозитории, но отдаёт его уже Timeweb Cloud: сервис App Platform, тип приложения **Frontend** (HTML/CSS/JS). Платить приходится за входящие запросы, для лендинга это несколько рублей в месяц. Так же устроен сайт Lightshelf.

После каждой отправки кода в ветку `main` Timeweb сам запускает `npm run build`. Команда копирует страницы и ассеты в папку `build/` (скрипт `scripts/build.mjs`), без служебных файлов вроде README и DEPLOY, и Timeweb отдаёт эту папку.

## Почему страницы лежат в папках

Сервер Timeweb для типа Frontend не умеет открывать `about.html` по адресу `/about`: такой адрес он отдаёт главной. Проверено 11 сентября 2026. Зато папки он понимает: `/about` перенаправляет на `/about/` и отдаёт `about/index.html`.

Поэтому каждая страница — это папка с `index.html`, а адреса заканчиваются слешем: `/about/`, `/blog/anatomiya-akcenta/`, `/en/business/`. Старые ссылки без слеша не ломаются, Timeweb перенаправляет их сам.

Вариант с Dockerfile и nginx, где адреса остаются без слеша, тоже рабочий, но стоит 510 ₽ в месяц. От него отказались.

## Настройки приложения

Названия пунктов в панели Timeweb могут немного отличаться от написанных здесь. Если что-то не находится, ориентируйтесь на смысл.

| Поле | Значение |
|---|---|
| Репозиторий и ветка | `Eri2410/bclear-lab-site`, `main`, сборка по последнему коммиту включена |
| Фреймворк | **React**, Node.js 22 или новее (сайт не на React: этот вариант просто запускает команду сборки и отдаёт её результат, так же настроен Lightshelf; у варианта HTML/CSS/JS поля команды сборки нет) |
| Команда сборки | `npm run build` |
| Зависимости | пусто |
| Директория сборки | `/build` |
| Регион | Москва |
| SPA Fallback (настройки веб-сервера) | **выключен** |

Если включить SPA Fallback, любой несуществующий адрес будет отдавать главную с кодом 200 вместо страницы 404. Поисковики сочтут такие адреса копиями главной.

## Проверка на техническом адресе

Технический адрес приложения виден на его дашборде, вида `…twc1.net`. После создания и после каждой пересборки он несколько минут может отвечать «can't be reached»: это нормально, надо подождать.

Открыть на нём:

- главная, `/about/`, `/faq/`, `/en/` открываются с оформлением;
- `/about` без слеша перенаправляет на `/about/`;
- `/blog/` и статьи блога открываются;
- `/какая-то-ерунда` показывает оформленную страницу 404, а не главную;
- `/README.md` тоже показывает 404: служебные файлы на сайт не попадают;
- `/sitemap.xml` и `/robots.txt` открываются.

Технический адрес можно прислать Claude: он прогонит эту проверку сам.

## Подключить домен

Приложение → **Домены** → добавить `bclearlab.ru` и `www.bclearlab.ru`. Панель покажет IP-адрес, на который должны указывать записи (IPv4 и, возможно, IPv6). Его нужно записать: он понадобится дальше. Если панель предлагает перенаправлять `www` на основной домен, включить.

## Переключить DNS

Лучше делать вечером или ночью: в промежутке между переключением и выпуском сертификата сайт по HTTPS может недолго открываться с ошибкой.

Домен переносить в Timeweb Cloud не нужно. Обычная панель Timeweb → **Домены и поддомены** → `bclearlab.ru` → **Настройки DNS**.

Для `bclearlab.ru`:

1. Удалить четыре A-записи GitHub: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
2. Удалить четыре AAAA-записи GitHub: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`. Если их оставить, пользователи с IPv6 продолжат попадать на GitHub.
3. Добавить A-запись на IP из панели приложения. Если Timeweb Cloud дал и IPv6, добавить AAAA-запись на него.

Для `www`:

1. Удалить CNAME на `eri2410.github.io`.
2. Добавить A-запись (и AAAA, если есть) на те же адреса, что у `bclearlab.ru`.

Не трогать TXT-записи `v=spf1 redirect=_spf.yandex.net` и `yandex-verification: …`, записи MX и запись для `app`. От них зависят почта, Яндекс Вебмастер и сервис.

## Дождаться и проверить

1. Записи обновляются от нескольких минут до пары часов. Проверка: `https://dns.google/resolve?name=bclearlab.ru&type=A` должен показать новый IP вместо `185.199.…`.
2. Сертификат Let's Encrypt Timeweb Cloud выпустит сам, когда DNS заработает. Это может занять до часа.
3. Открыть `https://bclearlab.ru` и `https://www.bclearlab.ru`, пройтись по списку проверки. Проверить, что Метрика видит визиты и форма листа ожидания работает.

## Выключить GitHub Pages

Через день-два, когда станет ясно, что всё работает:

1. GitHub → репозиторий `bclear-lab-site` → Settings → Pages → Source: **None** (или **Unpublish site**).
2. Удалить из репозитория файлы `CNAME` и `.nojekyll`: они нужны были только GitHub Pages.
3. По желанию сделать репозиторий приватным: Settings → Danger Zone → Change visibility. Timeweb собирает и из приватного репозитория, доступ у него есть через приложение Timeweb Cloud на GitHub. Раньше этого делать нельзя: бесплатный GitHub Pages работает только с публичными репозиториями.

## Если что-то пошло не так

- **Несуществующий адрес показывает главную** — включён SPA Fallback или директория сборки не `build`.
- **Страница открывается без оформления** — в ней путь к ассетам без слеша в начале (`assets/…`). Внутри папки он ведёт в несуществующую `/about/assets/`. Пути к ассетам пишутся только от корня: `/assets/…`.
- **Сборка падает** — посмотреть лог во вкладке «Деплой». Сборке нужен только Node.js, зависимостей нет.
- **`https://bclearlab.ru` открывается с ошибкой сертификата** — сертификат ещё выпускается, подождать час. Если дольше, проверить, что в DNS не осталось записей GitHub.
- **Часть посетителей видит старую версию сайта** — осталась AAAA-запись GitHub или у провайдера закэширована старая запись. Проверить DNS, подождать.
- **Откатиться назад** — вернуть в DNS записи GitHub. GitHub Pages продолжит работать, пока его не выключили; папки он тоже понимает.

## Новая страница

1. Папка с `index.html`: `имя/index.html`, для английской — `en/имя/index.html`, для статьи — `blog/имя/index.html`.
2. Ссылки на неё — со слешем на конце: `/имя/`.
3. Пути к ассетам — от корня: `/assets/…`.
4. Добавить адрес со слешем в `sitemap.xml` и в `<link rel="canonical">`.
