# Переезд сайта с GitHub Pages на Timeweb Cloud

Сайт остаётся в этом репозитории, но отдаёт его уже Timeweb Cloud. Сервис App Platform собирает контейнер по `Dockerfile`: внутри nginx с настройками из `nginx.conf`, которые повторяют GitHub Pages. Адрес `/about` открывает `about.html`, `/blog` перенаправляет на `/blog/`, а для несуществующей страницы отдаётся `404.html` с кодом 404. После каждой отправки кода в ветку `main` Timeweb пересобирает сайт сам, так что порядок работы с репозиторием не меняется.

Домен переносить в Timeweb Cloud не нужно. DNS `bclearlab.ru` остаётся в обычной панели Timeweb, там меняются только записи для сайта.

Переезд идёт без простоя: сначала сайт поднимается на техническом адресе Timeweb, и только когда там всё работает, домен переключается на новый сервер. До этого момента GitHub Pages продолжает работать как раньше.

Названия пунктов в панели Timeweb могут немного отличаться от написанных здесь. Если что-то не находится, ориентируйтесь на смысл шага.

## Шаг 1. Отправить файлы в репозиторий

В ветку `main` нужно отправить `Dockerfile`, `nginx.conf`, `.dockerignore` и этот файл. GitHub Pages на них не реагирует, а на сайт они не попадут: `.dockerignore` не пускает служебные файлы в контейнер.

## Шаг 2. Создать приложение

1. Timeweb Cloud → **Apps** (App Platform) → **Создать**.
2. Тип — **Dockerfile** (он может находиться внутри раздела Backend).
3. Регион — Россия (Москва или Санкт-Петербург).
4. Тариф — самый маленький: nginx со статичными страницами почти не нагружает сервер.

## Шаг 3. Подключить репозиторий

1. Источник кода — **GitHub**, аккаунт `Eri2410` уже подключён для сервиса `bclear-app`.
2. Timeweb видит только те репозитории, к которым ему дали доступ. Если `bclear-lab-site` нет в списке: GitHub → Settings → Applications → Timeweb Cloud → Configure → добавить `bclear-lab-site`.
3. Репозиторий `bclear-lab-site`, ветка `main`, автоматическая пересборка включена.

## Шаг 4. Настройки

| Поле | Значение |
|---|---|
| Директория проекта (где лежит Dockerfile) | корень репозитория, поле пустое или `/` |
| Порт | `80` (если панель спрашивает; он же указан в `Dockerfile`) |
| Проверка состояния (health check) | `/healthz` |

Переменные окружения не нужны.

## Шаг 5. Проверить на техническом адресе

Когда сборка закончится, Timeweb выдаст технический адрес приложения. Откройте на нём:

- `/healthz` показывает `ok`;
- главная, `/about`, `/faq`, `/en/` открываются с оформлением и шрифтами;
- `/blog` перенаправляет на `/blog/`, статьи блога открываются;
- `/какая-то-ерунда` показывает оформленную страницу 404;
- `/sitemap.xml` и `/robots.txt` открываются.

Технический адрес можно прислать Claude: он прогонит эту проверку сам.

## Шаг 6. Подключить домен в Timeweb Cloud

Приложение → **Домены** → добавить `bclearlab.ru` и `www.bclearlab.ru`. Панель покажет IP-адрес, на который должны указывать записи (IPv4 и, возможно, IPv6). Его нужно записать: он понадобится на следующем шаге.

С `www` nginx сам перенаправляет на `bclearlab.ru`.

## Шаг 7. Переключить DNS

Лучше делать вечером или ночью: в промежутке между переключением и выпуском сертификата сайт по HTTPS может недолго открываться с ошибкой.

Обычная панель Timeweb → **Домены и поддомены** → `bclearlab.ru` → **Настройки DNS**.

Для `bclearlab.ru`:

1. Удалить четыре A-записи GitHub: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
2. Удалить четыре AAAA-записи GitHub: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`. Если их оставить, пользователи с IPv6 продолжат попадать на GitHub.
3. Добавить A-запись на IP из шага 6. Если Timeweb Cloud дал и IPv6, добавить AAAA-запись на него.

Для `www`:

1. Удалить CNAME на `eri2410.github.io`.
2. Добавить A-запись (и AAAA, если есть) на те же адреса, что у `bclearlab.ru`.

Не трогать TXT-записи `v=spf1 redirect=_spf.yandex.net` и `yandex-verification: …`, записи MX и запись для `app`. От них зависят почта, Яндекс Вебмастер и сервис.

## Шаг 8. Дождаться и проверить

1. Записи обновляются от нескольких минут до пары часов. Проверка: `https://dns.google/resolve?name=bclearlab.ru&type=A` должен показать новый IP вместо `185.199.…`.
2. Сертификат Let's Encrypt Timeweb Cloud выпустит сам, когда DNS заработает. Это может занять до часа.
3. Открыть `https://bclearlab.ru` и `https://www.bclearlab.ru`, пройтись по списку из шага 5. Проверить, что Метрика видит визиты и форма листа ожидания работает.

## Шаг 9. Выключить GitHub Pages

Через день-два, когда станет ясно, что всё работает:

1. GitHub → репозиторий `bclear-lab-site` → Settings → Pages → Source: **None** (или **Unpublish site**).
2. Удалить из репозитория файлы `CNAME` и `.nojekyll`: они нужны были только GitHub Pages.

Репозиторий остаётся: Timeweb собирает сайт из него.

## Если что-то пошло не так

- **Сборка падает на строке `FROM nginx`** — Timeweb не смог скачать образ nginx с Docker Hub. Повторить сборку; если не помогает, спросить поддержку Timeweb, какое зеркало Docker Hub у них работает.
- **Страницы без `.html` отдают 404** — Timeweb собрал не тот Dockerfile или не из корня репозитория. Проверить поле «Директория проекта».
- **`https://bclearlab.ru` открывается с ошибкой сертификата** — сертификат ещё выпускается, подождать час. Если дольше, проверить, что в DNS не осталось записей GitHub.
- **Часть посетителей видит старую версию сайта** — осталась AAAA-запись GitHub или у провайдера закэширована старая запись. Проверить DNS, подождать.
- **Откатиться назад** — вернуть в DNS записи GitHub из шага 7. GitHub Pages продолжит работать, пока не выполнен шаг 9.

## Локальный просмотр

Не меняется: `python3 serve-site.py` в папке уровнем выше, порт 8765.
